# 第三阶段：漏洞知识库

## 架构评审

- 评审结论：通过，必须满足签名校验、不可变发布版本、原子激活和可观测同步记录。
- 判定边界：知识库保存厂商公告及其发行版修复版本，扫描阶段必须优先使用厂商公告；仅靠上游版本无法判断 backport 时输出“需人工确认”。
- 国内来源：CNVD、CNNVD 默认 `offline_package`，不依赖不稳定的在线 API；在线接入仅保留为次要扩展。
- 签名算法：离线包使用 Ed25519，服务端只配置可信公钥。签名、结构或大小校验失败时不创建公告和发布版本，仅保留失败审计记录。
- 发布模型：每次成功导入生成不可变快照并原子切换为活动版本；历史版本可一键回滚，扫描任务后续固定引用发布版本。
- 可观测性：离线导入和在线同步统一写入同步记录，展示模式、状态、校验键、摘要、条目数、时间和失败原因。

## 离线包格式

离线包是 UTF-8 JSON，签名针对文件原始字节。顶层包含 `schema_version`、`package_id`、`version`、`name`、`source_name`、`published_at` 和 `advisories`。每条公告必须包含 CVE、厂商公告号、发行版、严重性、厂商链接以及受影响软件包和修复版本。

## 页面设计

知识库页面由汇总指标和四个页签组成：公告库、数据源、发布版本、同步记录。主操作“导入签名包”在页头，回滚操作只出现在非活动版本，国内离线源不展示误导性的在线同步按钮。

## 验收范围

- 有效签名包可导入并自动成为当前版本。
- 签名被篡改或可信键不存在时拒绝公告入库。
- 公告可按 CVE、标题、公告号、系统和严重性筛选。
- 历史版本可回滚，当前公告视图随活动版本切换。
- 同步记录能区分完成和失败并展示校验信息。

## 定时更新

服务端每天检查已配置的在线厂商连接器。连接器必须提供 HTTPS 数据包地址、HTTPS 原始签名地址和已登记的密钥标识；下载后仍经过 Ed25519、包结构、来源和版本摘要校验。未配置连接器时调度器保持静默，界面显示“待配置”。CNVD/CNNVD 不参与定时在线下载。
